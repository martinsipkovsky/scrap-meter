Reading the data (Power BI, Excel, SQL)

Reports read the data straight from the database with a read-only login. They use the powerbi_* views below: together they hold all counted data with the station names filled in, keep their columns when the app is updated, and leave out passwords and tokens.

What you can read
ViewHolds

Times are UTC (the …_utc columns). In powerbi_readings a device reading holds the device's own counters (raw_ok / raw_nok) and the running totals of its job (total_ok / total_nok); the parts made between two readings are the difference of the totals. A manual entry (manual_entry true) holds the parts entered in raw_ok / raw_nok. With the app's own database login (administrators) the tables behind the views can be read too: stations, devices, readings, counter_states (totals per station and job), station_comments and notification_logs.

Power BI Desktop
  1. Home → Get data → More… → PostgreSQL database → Connect.
  2. Server: host:port, Database: —. Pick Import (or DirectQuery for live data) → OK.
  3. Sign in on the Database tab with the read-only user and password above.
  4. If Power BI says the connection isn't encrypted: the app's database has no TLS. Click OK to connect without encryption (or in File → Options and settings → Data source settings → this source → Edit permissions, clear Encrypt connections).
  5. Tick the powerbi_* views you need (comments: powerbi_station_comments) → Load.
  6. Scheduled refresh in the Power BI service: install the on-premises data gateway on a PC in the plant network that reaches this server, add a PostgreSQL data source to it with the same server, database, user and password, and pick that gateway in the semantic model's settings.
Excel
  1. Data → Get Data → From Database → From PostgreSQL Database.
  2. Server and database as above. Under Advanced options you can paste one of the SQL queries below.
  3. Sign in on the Database tab with the read-only user, pick the views → Load. Data → Refresh All reads the latest data.

Backups

Take a backup regularly and keep it somewhere other than this server, for example with the automatic FTP backup below. A backup holds all app data: devices, stations, readings, counters, comments, users and notification settings.

Download backup

Import this backup?

Importing replaces all current data (devices, readings, counters, users, notification settings) with the data in the file. The current data is saved first as a backup on this server, listed below, so the import can be undone by importing that file. You will be signed out and sign in with an account from the backup.

Automatic backup to FTP

Each run uploads one file named cognex-backup-DATE-TIME.json.gz and deletes the oldest of those files in the folder beyond the number to keep. Other files in the folder are not touched. Restore one with Import backup above.

Use a different database

The app runs inside a container, so localhost means the app container itself. Use the IP or name of the machine running PostgreSQL.
A saved database is used after the app restarts. If it cannot be reached at startup, the app falls back to the default (DATABASE_URL) and shows a warning here.
